# Cafe Lumière

架空のカフェを紹介する、HTML・CSS・JavaScriptだけで構成した3ページのWebサイトです。ビルドや外部ライブラリは不要です。

## 起動

Node.js 18以上を用意し、このフォルダで以下を実行します。

```sh
npm start
```

ブラウザで http://127.0.0.1:4173 を開きます。終了は Ctrl+C です。簡易確認なら `dist/index.html` を直接開くこともできます。地図の読み込みにはインターネット接続が必要です。


## 構成と更新箇所

```text
dist/
  index.html           トップページ
  menu.html            メニューとカテゴリ絞り込み
  information.html     店舗情報・参考マップ・お問い合わせ
  assets/
    style.css          配色・レイアウト・スマホ対応
    main.js            ナビゲーション・絞り込み・地図・入力確認
    cafe-hero-480.webp   小画面用のAI生成画像
    cafe-hero-960.webp   標準画面用のAI生成画像
    cafe-hero-1440.webp  大画面用のAI生成画像
    favicon.svg        オリジナルの文字アイコン
server.cjs             ローカル確認用サーバー
package.json           起動・構文確認コマンド
```

各HTMLは独立したページです。ヘッダーやフッターを変更する場合は3ページに反映してください。スタイルと振る舞いは共通ファイルへ分離しています。配色は `style.css` 冒頭のCSS変数で変更できます。ホスティング時は `dist` の内容を公開ディレクトリに配置します。

## 確認方法

`npm run check` でJavaScriptの構文、ローカル参照・アンカー、画像候補、ナビゲーション、カテゴリ絞り込み、地図の遅延読み込み、デモフォームの有効・無効入力時の処理を確認できます。外部パッケージのインストールは不要です。操作のテストはDOMの代替を使用するため、ブラウザの描画や標準入力検証そのもののテストではありません。起動後は次を手動確認してください。

- 3ページ間のリンクと、現在ページの表示
- 画面幅375px・768px・1440pxでの表示、スマホのメニュー開閉
- Tabキーでの操作、本文へのスキップ、フォーカス表示
- メニューの各カテゴリと「すべて」の切り替え
- 空欄、不正なメール形式、10文字未満の本文、未チェック時の入力検証
- 正常入力で「送信されていません」と表示され、ページ遷移しないこと
- Googleマップは表示ボタンを押して初めて読み込まれること
- Instagram・Googleマップへの外部リンク

## デモの範囲

店舗は実在しません。所在地・徒歩時間・席数・営業時間・価格・商品説明は仮データです。電話番号や実在店舗の詳細住所は掲載していません。Googleマップは実在する清澄白河駅周辺の参考表示であり、店舗の位置ではありません。地図表示時はGoogleに接続します。

SNSリンクはInstagramのサービス公式トップへのリンクです。架空店舗の公式アカウントではありません。実運用では正しいアカウントへ差し替えてください。

お問い合わせフォームはブラウザ内の入力検証のみです。送信API、メール送信、データ保存、アクセス解析はありません。個人情報を入力しないよう表示しています。実運用にはサーバー側検証、迷惑送信対策、送信先、プライバシーポリシー、適切な個人情報管理を実装してください。

## 画像・アクセシビリティ

カフェ写真はこの制作のためのAI生成画像です。実在店舗の写真やロゴは使用していません。商品イラストはHTML内のオリジナルSVG、ロゴは文字組みです。外部フォントや画像CDNへの依存はありません。

日本語の文書言語、見出し構造、ランドマーク、画像代替文、フォームラベル、必須項目、状態通知、キーボード操作、動きの軽減設定に対応しています。WCAG準拠を認証するものではありません。

## GitHub Pagesで公開する

このフォルダ全体を**リポジトリのルート**に置く構成です。`dist` だけをリポジトリに入れるのではなく、隠しフォルダ `.github` と `.gitignore` も含めてアップロードしてください。`.git` と `.openai` は含めません。

1. ZIPを展開し、GitHubに公開用リポジトリ（例：`cafe-lumiere`）を作成します。無料アカウントなら公開リポジトリを使用します。READMEの自動生成はオフで構いません。
2. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定します。
3. このフォルダの内容を `main` ブランチへ追加します。Gitを使う場合は新しい空フォルダにZIPを展開して、以下を実行します。`YOUR_NAME` は実際のユーザー名へ置き換えてください。

```sh
git init
git add .
git commit -m "Prepare Cafe Lumiere portfolio"
git branch -M main
git remote add origin https://github.com/YOUR_NAME/cafe-lumiere.git
git push -u origin main
```

4. **Actions** タブで **Deploy Cafe Lumière to GitHub Pages** の成功を確認します。設定後に自動実行されていなければ **Run workflow** で実行してください。
5. 実行結果の `github-pages` 環境、または **Settings → Pages → Visit site** のURLを開きます。通常のプロジェクト用URLは `https://YOUR_NAME.github.io/cafe-lumiere/` です。
6. 公開先で3ページ、画像、メニュー切り替え、マップ、フォームのデモ表示を確認します。更新はファイルを変更して `main` にpushすると反映されます。

ワークフローは構文・参照・動作の自動確認後、`dist` のみを公開します。README、確認スクリプト、ローカルサーバーはWebサイトへ配信しません。ビルドやnpm install、独自のアクセストークン登録は不要です。ブランチ名が `main` 以外の場合は `.github/workflows/pages.yml` の `branches` を変更してください。実際のリポジトリへのpushと公開はまだ行っていません。

参照：[GitHub公式・カスタムワークフロー](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)、[公開元の設定](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。

### 公開後に表示されない場合

- 404：PagesのSourceがGitHub Actionsか、Actionsが成功したか、URLのリポジトリ名が正しいか確認します。
- デプロイ失敗：Actionsの失敗ステップを確認します。環境の保護ルールや組織のActions権限制限も確認します。
- 画像やCSSだけ表示されない：ファイル名の大文字小文字を確認し、`assets/...` の相対パスを維持してください。先頭に `/` を付けるとプロジェクトURLで参照先が変わります。
- 更新が古い：最新のActionsが完了してからブラウザを再読み込みします。
- マップが表示されない：ネットワークやコンテンツブロックを確認し、併記したGoogleマップへのリンクを利用します。
